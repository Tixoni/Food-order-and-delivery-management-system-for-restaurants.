Перед замером WebSocket соединения открывались группами по пять. Задержка считалась от отправки координаты до её получения последним из 200 подписчиков.

Короткий прогон использовал `LOAD_PROFILE=sample`. Для проверки устойчивости под длительной нагрузкой в сценарии есть `LOAD_PROFILE=peak` с плато 20 минут.

Команда для замера старта: `npm run env:prepare -- --no-build --geo`. В замер входят миграции и подготовка демоданных. Сборка образов и подготовка карты выполнялись заранее.

## Финальные проверки

- ESLint, Prettier и сборка TypeScript и Vite прошли.
- Jest выполнил 547 модульных тестов с измерением покрытия.
- На отдельном PostgreSQL/PostGIS прошли 28 интеграционных тестов. Чистые миграции применены, повторный запуск оставил схемы без изменений.
- На финальном стенде заказ №2 доставлен. Заказ №3 отменён оператором с возвратом 100 копеек, сумма подтверждена в платёжной БД.
- Проверка в Chrome подтвердила вход оператора, поиск по номеру, открытие истории и разграничение доступа для клиента.
- Повторное восстановление снимка возрастом 4 с заняло 6 с. В копии 50 ресторанов, 20 курьеров, 3 заказа и 3 платежа.
- `npm audit --omit=dev` выявил 24 замечания в существующих зависимостях, включая 11 уровня high. Критических замечаний в runtime-аудите нет.
