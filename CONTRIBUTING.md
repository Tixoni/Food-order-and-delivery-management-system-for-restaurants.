# Соглашения по работе с репозиторием

## Сообщения коммитов

Формат: `<тип>(<область>): <краткое описание>`

Описание — в повелительном наклонении, без точки в конце, до 72 символов.

**Типы:**

| Тип        | Когда                                  |
| ---------- | -------------------------------------- |
| `feat`     | новая функциональность                 |
| `fix`      | исправление дефекта                    |
| `refactor` | изменение кода без изменения поведения |
| `test`     | добавление или правка тестов           |
| `chore`    | инфраструктура, зависимости, настройки |
| `docs`     | документация в репозитории             |
| `perf`     | изменение ради производительности      |

**Области:** `catalog`, `order`, `payment`, `delivery`, `gateway`, `web`, `shared`, `contracts`, `infra`, `ci`, `spikes`.

Примеры:

```
feat(catalog): расчёт цены блюда с модификаторами
fix(order): повторная отправка формы больше не создаёт дубль заказа
chore(infra): окружение с PostgreSQL, Redis и Kafka
```

Тело сообщения — если нужно объяснить, **почему** сделано именно так. Что сделано, видно из изменений.

## Ветвление

Магистральная разработка: короткие ветви от `main`, слияние после зелёной проверки. Долгоживущих ветвей нет.

## Правило зависимостей между слоями

```
domain          ← ничего не импортирует извне
   ↑
application     ← знает domain, работает с портами
   ↑
infrastructure  ← реализует порты
interface       ← принимает запросы
```

Домен не знает о базе, брокере и сети. Слой `application` описывает нужные операции интерфейсами (портами), а `infrastructure` их реализует.

**Правило проверяется автоматически.** Попытка обратиться из домена к `typeorm`, `kafkajs`, `@nestjs/*` или к слоям `infrastructure`/`interface` останавливает проверку кода с ошибкой. Это сделано намеренно: архитектурное ограничение, которое не проверяется машиной, рано или поздно перестаёт соблюдаться.

## Проверка перед коммитом

```bash
npm run check
```

Выполняет проверку форматирования и правил кода. Автоисправление — `npm run lint:fix` и `npm run format`.

## Что не попадает в репозиторий

Файлы окружения с секретами, данные карт, содержимое баз, сборки, зависимости. Полный список — в `.gitignore`. Результаты исследований и проектные заметки ведутся отдельно и в репозиторий не коммитятся.
